# Work A-R1：攻击强度幅度敏感性结果

在原六资产合成模型上，仅将第 5–8 槽 API 攻击由平时的 0.20 提高至 0.30（S1）或 0.40（S2）。Web 始终 0.40，防御容量 1.2 不变，S2 执行结果复用原实验 A。第 5 槽匹配对照的状态、剩余 8 槽时域和求解初值完全相同，仅改变持续预测的 API 输入。

| API 预测强度 | 第 5 槽网关隔离 | 恢复 | 资源占用 | 全网资源占用 |
|---:|---:|---:|---:|---:|
| 0.20 | 0.184245 | 0.281059 | 0.465304 | 1.200000 |
| 0.30 | 0.194305 | 0.273225 | 0.467530 | 1.200000 |
| 0.40 | 0.204387 | 0.266324 | 0.470711 | 1.200000 |

**首槽响应与后续不同。** 从 0.30 升到 0.40，网关首槽隔离增加 0.010082、恢复减少 0.006901，资源净增 0.003181；其他五资产资源均减少，其中 Web 首槽减少约 0.000957。订单处理与身份认证的首槽隔离却是先小幅增、再减。对第 5 槽作出的整份预测计划，网关恢复在第 6–12 槽随强度上升而增加，方向与首槽相反；网关资源在八个预测槽都依次增加。部分其他资产资源方向随槽而变，例如订单资源的 0.40−0.30 差同时出现正、负值。槽 5–7 三档配置均用满容量，首槽重新分配并非总资源增加；槽 8 以后容量的松紧因强度和时段而异。

各场景内 C1/C2 使用同一实际输入。S1 累计加权受损损失减少 0.035218、行动成本合计增加 0.032085；S2 相应为 0.068411、0.057355。隔离约束来源传播、恢复作用于本资产受损，且共享容量和行动成本共同制约分配；这些模型结构与首槽的行动替换和后续恢复增加相容，但未单独识别任何一项的因果贡献。两档均非逐时占优：S1 网关、数据库及全网均值也曾短暂高于 C1，Web 受损未降低。图仅画匹配首槽，后续预测并不等同实际执行到槽 12；槽 9 会重新规划。

## 论文 4.2 节候选表述

在同一第 5 时段起始状态下，将 API 网关预测攻击强度由 0.20 提高至 0.30、0.40，首时段网关隔离强度依次上升、恢复强度依次下降，资源占用由 0.46530 增至 0.46753 和 0.47071；同期总容量均用满。后续预测时段的网关恢复则随攻击增强而提高，表明响应方向与所处时段有关。对两条实际攻击轨迹分别比较，事件重规划使综合损失下降 0.0389% 和 0.1322%。这支持所测试幅度下的局部数值敏感性和小幅净收益，不支持一般单调性、全局最优或双方纳什均衡。
